# Windows preview review

Scope: local Rust/Tauri build, notch interactions, provider presentation,
installer and update path. This is a focused code/runtime review, not a completed
cross-platform end-to-end certification. No independent Claude review was run.

## Findings to address before a public release

1. **P1: installing a new version can leave the old version running.**
   `scripts/install-native.ps1:13` stops only the executable in the NEW version
   directory. The existing previous-version process survives. The single-instance
   handler in `native/codenotch/src/main.rs:1698` can then redirect the new launch
   to the old process. Our development installs manually stop the exact old path;
   the installer itself must perform a scoped old-version handoff. Never terminate
   the separate original CodeNotch or MATRA-V2 processes by executable name alone.

2. **P1 before adding more accounts: fixed viewport has no overflow strategy.**
   `main.rs:45,285` keeps the long dimension at650 design pixels; the notch uses
   `overflow:hidden`, but `claudeCells()` can produce multiple account rows.
   Eight standard rows alone need roughly658px before external handles. Add an
   overflow menu, pagination or an explicitly bounded account selection, then test
   1/6/8/12 accounts on all edges and scales. Current12 geometry cases use the
   installed provider count and do NOT cover arbitrary account counts.

3. **P2: transparent hit region is broader than the visible controls.**
   `main.rs:927` treats the bounding rectangle of every hot rectangle as inside.
   With a tooltip and satellites, transparent corners also stop click-through.
   Replace the blanket bounding rectangle with explicit narrow bridges; test
   clicks on a harmless underlying test window, including hover transitions.

4. **P2: notch controls are mouse-only.**
   `ui/notch.html` move/orb are divs with no role, accessible name, tab stop or
   keyboard action. Settings has alternate access, but these controls themselves
   are not keyboard accessible. Design keyboard/focus behaviour without stealing
   focus from the editor; keep the existing gear artwork.

## Known product gaps, not newly discovered regressions

- Glass is smoked translucency, not native desktop blur.
- Auto-update is intentionally disabled: no endpoint and placeholder signing key.
  Public release needs an owned signed update feed and rollback testing.
- Mac provider parity is incomplete. Adding providers needs a common reading
  contract (quota vs count vs local runtime) and provider-by-provider auth tests.
- Native adapters and Mac Swift implementation do not yet share a runtime core.

## Verification limits

Automated checks cover Rust logic, rendered ring thresholds, themes, dimensions
and independent handle reveal states. Programmatic browser events are not proof
of physical pointer behaviour. Still test real mouse travel, dragging across
mixed-DPI monitors, sleep/resume, taskbar relocation, expired credentials,
offline/reconnect and fresh install/upgrade. The earlier hover-hide regression
was not conclusively diagnosed; the new reveal tests must not be presented as a
complete fix for every pointer-state race.
The older native-layout-test.js expects both handles visible on body hover and
contains a previously failing asynchronous hide assertion. It is not a green
release gate for preview.11; update its obsolete visibility contract, retain and
isolate the unresolved real-pointer hide coverage. New native-handle-test.js
verifies the newly approved independent reveal contract, not that old race.

## Independent review brief

Ask Codex and Claude separately to review this same source snapshot, read-only.
Require severity, file/line, reproduction and a minimal fix for every finding.
Have one focus on native window/hit-testing/authentication and the other on UI
state, accessibility, data semantics and installation. Compare reproducible
findings, not model votes. Do not let both edit the same working tree concurrently.
